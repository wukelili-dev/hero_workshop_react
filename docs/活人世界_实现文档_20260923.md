# 活人世界 · 实现文档（交给实现 Agent）

> 目标读者：负责实现本模块的 agent。
> 本文件是**规格**，不是代码；请按第 5 节的阶段顺序实现，每阶段一次 commit。
> 一句话目标：**让世界在玩家不操作时也自己在变，并且会主动找上玩家。**

---

## 0. 为什么要做这个（问题定义）

项目已经有 42 个 NPC、条件对话引擎、关系网、记忆、日推进与 46 条渠道规则，但玩家体感"还是不像太吾绘卷"。
根因**不是内容量不够，而是世界没有自主性**：

- 玩家点 NPC → 才有事发生；不点 → 世界静止。
- 日推进只在"写日志"：`addEvent()` 一条文本 + `±几金` + 改 `mood`，**没有任何一条会改变世界状态**。
- NPC 永远不会主动找玩家。

太吾的"内容"其实不多，它的核心是**自主体 + 目标 + 后果 + 长线演化**。本模块就是把这条模拟层补上。

### 1.2 三个已核实的断点（本模块要修的就是它们）

1. **日推进只写文本**：`advanceNpcDay()` 的写操作只有 `addEvent()` / `modifyNpcGold(±小钱)` / `patch(mood)`。
2. **NPC 没有"自己的东西"**：`NpcEcoState` 只有 `mood/bond/memory/flags/cooldowns/saidOnce/health/enemies/benefactors/lastActiveDay` —— 没有战力、资产、目标、归属。
3. **没有主动来访入口**：全项目搜不到 NPC 主动发起的交互。`src/data/npcs.ts` 里「门派 / sect」命中 **0 次**。

## 3. 数据模型（可直接抄）

追加到 `src/types.ts`：

```ts
/** NPC 自己的"面板"：没有它，NPC 就永远停在原地等你点 */
export interface NpcSelfState {
  power: number;            // 战力（与玩家等级同量级，用于上门战斗/切磋）
  assets: number;           // 资产（金币之外的产业估值，影响语气与出手）
  injuries: number;         // 0~100，受伤会降 power、改台词
  factionId?: string;       // 所属势力
  goal: NpcGoal;            // 当前目标，驱动每日行动
  reputation: number;       // 在本地据点的名望
}

export interface NpcGoal {
  kind: 'wealth' | 'power' | 'revenge' | 'love' | 'fame' | 'wander';
  target?: string;          // 复仇/求爱目标（npc id）
  progress: number;         // 0~100
}

export interface Faction {
  id: string;
  name: string;
  kind: 'sect' | 'guild' | 'court' | 'temple' | 'tribe';
  homePlace: string;        // 据点 id（对应 MAPS id）
  power: number;
  description: string;
}

/** 待上门的行动：日推进时生成，到日子触发 */
export interface PendingVisit {
  id: string;
  npcId: string;
  kind: 'revenge' | 'challenge' | 'beg' | 'gift' | 'matchmake' | 'report';
  createdDay: number;
  arriveDay: number;
  reason: string;           // 为什么来（引用记忆/flags，如"你偷过他"）
  resolved?: boolean;
}

/** 跨系统后果：声望/恩怨带来的价格、拒卖、封锁、任务 */
export interface Consequence {
  id: string;
  kind: 'price' | 'ban' | 'block' | 'quest' | 'service';
  scope: { factionId?: string; npcId?: string; placeId?: string };
  value: number;            // 价格系数 / 封禁天数 / 任务 id
  untilDay: number;
  reason: string;
}
```

存放位置：

| 数据 | 静态/运行时 | 位置 |
|---|---|---|
| `NpcGoal` 初值、`NpcSelfState` 初值 | 静态推导 | `npcEcology.buildEco()` 或新增 `buildSelf()` |
| `Faction` 定义与成员 | 静态 | 新增 `src/data/factions.ts` |
| `NpcSelfState` | 运行时（存档） | `useNpcEcoStore.states[id]` 内新增字段 |
| `PendingVisit[]` | 运行时（存档） | `useWorldStore.visits` |
| `Consequence[]` | 运行时（存档） | `useWorldStore.consequences` |
| 玩家对每个势力的声望 | 运行时（存档） | `useWorldStore.factionRep: Record<string, number>` |

## 4. 子系统规格

每个子系统都必须满足：**有触发条件、有状态变更、有玩家可见结果、有验收方法**。

### S1 NPC 自主体（最高优先）

**改造 `advanceNpcDay()`**：活跃 NPC（当前据点 + 与玩家 affinity ≥25，上限 12 个）每天按 `goal.kind` 执行 1 个行动，**行动必须改数值**：

| goal | 每日行动 | 状态变更 |
|---|---|---|
| `power` | 修炼 / 寻师 | `power += 3~8`，`reputation += 1` |
| `wealth` | 做买卖 / 收租 | `assets += 5~20`，`npcStore.modifyNpcGold(+15~40)` |
| `revenge` | 打探仇人 / 拉帮手 | `goal.progress += 10~25`；progress ≥ 60 时生成 `PendingVisit(kind:'revenge')` |
| `love` | 送礼 / 提亲 | 对目标的 `relationStrength` ±5；progress ≥ 80 生成 `matchmake` 事件 |
| `fame` | 摆摊 / 比武 | `reputation += 2~5`，可能生成 `challenge` 来访 |
| `wander` | 迁移 | 换 `location` 到邻近据点（可选，最简可不做） |

同时：

- NPC 之间的行动要写关系：`relationOverride` 或 `PROPAGATION` 的逆向使用（例如 A 拉了帮手 B → A↔B `strength +8`）。
- 每条行动都要产出 `WorldEvent`，且文本必须来自模板插值（`${name}` 等），**不许硬编码具体 NPC 名**。
- 战力公式建议：`power = 20 + level*6 + 装备/资产加成`，与 `Hero` 的 `atk` 同量级，便于直接用于上门战斗。

**验收**：连续推进 30 天（可写临时脚本或在开发时加速 `DAY_MS`），日志里至少有 5 次"NPC 状态发生可观察变化"（power/assets/relations/injuries），且每条都能追溯到原因。

### S2 主动来访（第二优先，玩家体感最强）

**新增 `src/engine/VisitSystem.ts`**：

- `enqueueVisit(npcId, kind, reason, delayDays)`、`tickVisits(day)`（在 `advanceNpcDay` 末尾调用）、`resolveVisit(visitId, choice)`。
- 触发来源：`revenge`（记仇 + progress≥60）、`challenge`（fame + power）、`beg`（玩家曾赠礼/救过）、`gift`（bond ≥ 好友）、`report`（玩家被通缉/偷窃被抓）。

**新增 `src/components/shared/VisitModal.tsx`**（水墨风，复用 `.ink-panel / .ink-btn / .ink-btn-seal`）：

> 「赵镖头带着两个镖师堵在巷口。」（原因：你偷过他的钱袋）
> 选项：**应战** / **破财消灾（付 {n} 金）** / **躲开（耗 1 天，关系再降）** / **找人帮忙（消耗某势力声望）**

结算（必须落状态）：

| 选择 | 后果 |
|---|---|
| 应战 | 复用 `executeBattle`（NPC 用 `power` 换算 hp/atk/def）；胜：对方 `injuries+30`、其势力声望 −10、生成悬赏；败：玩家掉 30% 金币、`health` 恢复延迟、对方 `mood=狂热` |
| 破财 | 扣金，`affinity +10`，flag `破财消灾`，恩怨 progress −40 |
| 躲开 | `advanceDays(1)`，对方 `mood=厌恶`，7 天内该 NPC 拒卖 |
| 求助 | 消耗某势力声望，改由该势力出面摆平（写 `Consequence`） |

**验收（写进测试剧本）**：偷赵镖头 → 3 天内弹出面板 → 四种选择各产生可验证的差异（钱/关系/声望/悬赏）。

### S3 势力层

**新增 `src/data/factions.ts`**（数据，不写逻辑）：长安示例——`changan_court`（官府，成员：魏征/唐太宗）、`changan_guild`（西市商会，老张头/孙二娘/裴绣娘）、`changan_escort`（龙门镖局，赵镖头）、`changan_temple`（佛门，玄奘/观音）、`yao_alliance`（妖盟，化羽鸮/混世魔王残将）。每个 NPC 通过 `factionId` 归属。

**新增 `src/engine/FactionSystem.ts`**：

- `repOf(factionId)` / `addRep(factionId, delta)`（存 `useWorldStore.factionRep`）。
- 声望效果（转成 `Consequence`）：≤ −30 → 该势力商人价格 ×1.3 且部分拒卖；≤ −60 → 封锁该据点（`InkMapPanel` 显示"此处已对你封城"）；≥ 40 → 解锁势力任务与庇护（被打时有人来帮）。

**验收**：击杀一名官府 NPC → `changan_court` 声望下降 → 官府 NPC 拒卖 + 出现悬赏；把声望刷回 ≥0 → 恢复交易。

### S4 对话即情报 / 谈判

在现有 `DialogueSystem`（`DialogueTree` / `DialogueNode` / `DialogueOption`）上新增两类节点：

- **intel**：选项返回**真实世界状态**（必须是查 store，不许写死文案）。可打听：某人现在在哪 / 与谁有仇 / 目标是什么 / 某势力当前对你的声望 / 某件秘宝在谁手上。
- **negotiate**：结盟 / 停战 / 借势 / 收买，用 `WorldEffect` 改 `relationShift`、`worldFlag`、势力声望。

**验收**：任选两名 NPC，打听"你与某某是什么关系"，返回值必须与 `useNpcEcoStore.relationStrength()` 当前值一致。

### S5 跨系统后果

- `useWorldStore.consequences` 为唯一出口；`buyNpcTradeItem` 结算前先查该 NPC 所属势力的 `price` / `ban`；`InkMapPanel` 的 `moveTo` 前查 `block`；悬赏榜可挂 `quest`。
- 后果必须有 `untilDay`，过期自动清理（在 `pruneEvents` 里一并 prune）。

### S6 呈现

- **事件时间轴**：人物志右侧新增"年表"（按天倒序，可只看与玩家相关）。
- **NPC 档案页**：战力 / 资产 / 归属势力 / 恩怨名单 / 当前目标 / 最近三次行动（数据都在 S1 里）。
- **势力图层**：在现有人物志 SVG 关系网上加一层（同势力同色底纹，敌对势力连线用朱色）。

## 6. 必须遵守的项目约定（摘自 AGENTS.md）

- **只 `git commit`，不要 `git push`**；小改动直接改，不要反问。
- 提交信息：`feat(scope): 摘要` + 多个 `-m` 正文；`git add` 只加本次相关路径。
- 改完必跑：`npx tsc -p tsconfig.app.json --noEmit`（0 错误）+ 浏览器实跑无 console 异常；动过数值跑 `node scripts/balance-sim.mjs`。
- 水墨风：只用 `src/index.css` 令牌与 `.ink-*` 类，不新增彩色 Tailwind 类；**不引入外部图片/字体**。
- 数据驱动：文案与规则进 `src/data/`，组件里不硬编码；所有台词走插值 `${self}/${call}/${name}/${title}/${catch}/${day}`。
- 存档兼容：新字段必须给默认值，并在 `loadEco` / `loadWorld` 里归一化（参考现有 `recentTopics` 的写法）。

## 8. 风险与陷阱

| 风险 | 规避 |
|---|---|
| store 循环依赖 | 现有安全方向：`useWorldStore → NpcAutonomy`、`NpcSystem → useWorldStore`；**不要**让 `NpcAutonomy` 反向 import `useWorldStore`（日事件已在 `useWorldStore.tick` 里写） |
| 事件风暴 / 存档膨胀 | 每天事件 ≤3 条、`PendingVisit` 未解决上限 3 条、事件保留 30 天、记忆保留 20 条 |
| 性能 | 日推进只处理 ≤12 个活跃 NPC，不进每帧循环；来访结算只在触发时算一次 |
| 文案与状态脱节 | 所有文本用插值；intel 节点必须查真实 store |
| 老档崩溃 | 每个新字段都在 `loadEco/loadWorld` 里 `?? 默认值` |
| 玩家被无限骚扰 | `PendingVisit` 同类 7 天冷却；被拒绝后 3 天不再来 |

## 9. 最少可感验证剧本（照着跑就能验收）

1. 进长安 → 据点 → 人物志 → 选**赵镖头** → 偷窃。
2. 把 `DAY_MS` 临时调小（或等待）推进 1~3 天 → **弹出「有人找上门」**，原因是"你偷过他的钱袋"。
3. 选**应战** → 战斗结算：胜则镖局声望 −10 且出现悬赏；败则掉 30% 金币。
4. 再去找**铁匠铺**买东西 → 若镖局/商会声望为负，价格上浮或直接拒卖。
5. 去找**胡姬**（赵镖头的恋人）→ 她对你的态度与台词随"你与赵镖头的关系"变化（关系网传导 + 专属台词）。
6. 打开人物志 → 赵镖头档案里能看到 `goal: revenge`、进度、最近三次行动；年表里能看到整条因果链。

**这 6 步全通，就说明"活人世界"最小闭环成立了**，之后再按 P1/P2 铺势力、对话情报与呈现。
